# 모바일 앱 — 결정 사항과 이유

작업 진행 중 결정한 내용을 시간순으로 누적. 다음 세션이 이 문서만 읽고 맥락을 잡을 수 있도록 작성.

---

## 2026-06-01 — 초기 의사결정

### 결정 1. 네이티브 신규 개발이 아닌 Capacitor 래퍼
- **선택**: Capacitor + Vercel 콘텐츠 로딩
- **대안 비교**
  - React Native 완전 재작성: 코드베이스 두 개, 6개월+ 일정, 기각.
  - PWA만 사용: 스토어 없음, 사용자 유입에 약함, 기각.
  - Bubblewrap(TWA): Android만 가능, iOS 별도 솔루션 필요, 후순위.
  - Capacitor: 1차 출시 빠르고 iOS 확장도 같은 코드 → **채택**.
- **근거**: 기존 Next.js·NextAuth·BAND 연동을 모두 재사용해야 함. 회사 단계가 1인 운영이라 코드베이스 분리 비용 큼.

### 결정 2. Android 먼저, iOS는 나중
- **이유**: 사용자가 현재 Mac 미보유. iOS 빌드는 Xcode 필수.
- **차선책 거부**: 클라우드 Mac 빌드(Codemagic 등)도 가능하지만 월 구독료가 발생하고, 어차피 출시 사이클을 두 번에 나누는 게 학습 부담도 적음.
- **재검토 시점**: Android 출시 후 다운로드 추이를 보고 iOS 진입 시점 결정.

### 결정 3. WebView 콘텐츠는 원격 URL 로딩 방식
- **선택**: `server.url = https://<vercel>` 방식.
- **대안**: Next.js `output: 'export'`로 정적 export해서 앱 번들에 포함하는 방식.
- **비교**
  - 원격 로딩: 업데이트 즉시 반영, 스토어 재심사 불필요. 단점은 오프라인 불가.
  - 번들 내장: 오프라인 동작 가능. 단점은 API route·SSR 사용 불가, 매번 스토어 재심사.
- **근거**: 이 서비스는 본질적으로 온라인(예약·BAND 크롤·DB 조회)이라 오프라인 가치가 0에 가깝다. 빠른 반영이 훨씬 가치 큼.

### 결정 4. 패키지 ID(applicationId) 정책
- **확정값**: `kr.co.thegolfer.app`
- **이유**: 운영 도메인이 `thegolfer.co.kr`이라 역순 표기와 정확히 일치. 한국 사업자 관행에도 맞음.
- **주의**: 한 번 출시하면 영원히 못 바꿈. iOS bundleId도 동일 값 사용 예정.

### 결정 4-bis. 운영 도메인 / 앱명 / 표시명 확정
- 도메인: `thegolfer.co.kr` (Vercel 커스텀 도메인)
- WebView `server.url`: `https://thegolfer.co.kr`
- 스토어 표시명: `더 골프`
- 패키지 ID: `kr.co.thegolfer.app`

### 결정 5. 1차 출시에 푸시 알림 미포함
- **이유**: FCM 셋업·서버 토큰 관리·동의 화면 등 부수 작업이 많음. MVP 출시 속도 우선.
- **재검토**: 출시 후 사용자 리텐션 데이터 보고 결정.

### 결정 6. Google Play 개인 vs 회사 계정
- **현재 미정**. 사용자 답변 대기.
- **차이**
  - 개인: $25 등록. **테스터 20명·14일 비공개 테스트 강제**.
  - 회사(사업자등록증 필요): $25 등록. 위 요건 면제, 바로 출시 가능.
- **권고**: 사업자등록증이 있거나 발급 가능하면 회사 계정으로. 부담스러우면 개인으로 진행하되 14일을 일정에 미리 반영.

### 결정 7. 외부 redirect 처리 정책
- **선택**: 외부 도메인은 시스템 브라우저(Chrome 등)로 위임.
- **이유**: BAND OAuth, 카드사 결제창 등은 WebView 내부에서 막히거나 쿠키 격리 문제로 인증 실패 가능. 시스템 브라우저로 위임하면 사용자 기존 세션도 활용 가능해 UX 향상.
- **구현**: `@capacitor/browser`의 `Browser.open()` + 딥링크 콜백.
